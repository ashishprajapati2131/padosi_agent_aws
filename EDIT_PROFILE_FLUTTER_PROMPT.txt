PADOSIAGENT — AGENT EDIT PROFILE FLOW
Flutter APK implementation prompt
Source of truth: FastAPI mobile API (mounted at /api) plus the website edit-profile screens.
Do not call the website form POST /agent/update-profile/ from the APK. That route is a Django session form. The APK must use the JWT APIs below.

================================================================================
0. HOW TO USE THIS PROMPT
================================================================================
Build the logged-in agent Edit Profile flow in the Flutter app so it matches the website and the live mobile API.

Rules for the Flutter agent:
- Auth on every /api/v1/agents/* call: header Authorization: Bearer <access_token>
- JSON bodies: Content-Type: application/json
- File uploads: multipart/form-data
- Base URL example: https://padosiagent.com
- FastAPI is mounted at /api. Router prefix is /v1/agents or /v1/pincode.
- Load the screen from GET /api/v1/agents/profile. That response is the single source of truth.
- Save one step at a time. Do not send the whole profile in one request.
- Each successful step save already sets agent status to pending_approval (unless status is suspended, blacklisted, or rejected). There is no separate "final submit" API on mobile.
- Several saves REPLACE child lists. If you omit a list, the server deletes those rows. Always send the current full list for that step.
- If features_access.<slug>.is_locked is true, show the section locked and do not call the write API for that section.
- Echo read-only values back unchanged. Sending an empty license_number clears the admin-verified IRDAI license.

================================================================================
1. SCREEN FLOW (STEP BY STEP)
================================================================================
Entry: agent dashboard -> Edit Profile.
First call: GET /api/v1/agents/profile
Then render 4 steps. The user can jump between steps. Previous does not save. Next validates, then saves, then moves forward.

STEP A — Basic Details                         (website visual step 1)
  Save: PUT /api/v1/agents/profile/basic
  Photo is NOT in that JSON. Photo is POST /api/v1/agents/profile/image
  On success -> go to Step B

STEP B — Professional                          (website visual step 2)
  Helper calls before save:
    GET  /api/v1/pincode/{pincode}                         when user enters a 6-digit pincode
    GET  /api/v1/agents/profile/serviceable-cities         city dropdown
    POST /api/v1/agents/profile/serviceable-cities         if user types a city that is not in the list
  Optional file calls (only if that feature is unlocked):
    POST   /api/v1/agents/profile/licenses/irdai
    DELETE /api/v1/agents/profile/licenses/irdai
    POST   /api/v1/agents/profile/licenses/amfi
    DELETE /api/v1/agents/profile/licenses/amfi
  Save text fields: PUT /api/v1/agents/profile/professional
  Lead Preferences live on this step (Configure button opens a sheet).
  If lead preferences are unlocked, include leadPreferences in the same professional PUT.
  If they are locked, omit leadPreferences (send null / leave the key out).
  On success -> go to Step C

STEP C — Product Portfolio                     (website visual step 3)
  Helper: GET /api/v1/agents/profile/companies
  Save: PUT /api/v1/agents/profile/portfolio
  On success -> go to Step D

STEP D — Additional                            (website visual step 4)
  These are their own APIs, not part of the additional JSON:
    POST   /api/v1/agents/profile/achievement
    DELETE /api/v1/agents/profile/achievement/{photo_id}
    GET    /api/v1/agents/profile/career-timeline
    POST   /api/v1/agents/profile/career-timeline
    PUT    /api/v1/agents/profile/career-timeline/{timeline_id}
    DELETE /api/v1/agents/profile/career-timeline/{timeline_id}
    GET    /api/v1/agents/profile/generate-bio          fills the bio box only; does not save
  Save website + social links + bio text:
    PUT /api/v1/agents/profile/additional
  On success -> open Declarations sheet (local only, no API field)

DECLARATIONS SHEET (local UI only)
  One required checkbox: "I have read, understood, and agree..."
  Bullet text to show:
    - All information provided is self-declared and accurate to the best of my knowledge
    - Leads are not guaranteed and depend on customer preferences and search criteria
    - PadosiAgent is a facilitation platform only and does not guarantee any business
    - PadosiAgent does not charge any commission on policies sold or claims processed
    - Any disputes shall be subject to the jurisdiction of courts in Ahmedabad, Gujarat
  Note under the checkbox: "Your profile will be reviewed by our team within 24-48 hours."
  Submit button only checks the checkbox. Do not invent a submit endpoint.
  After the user agrees, pop back to the dashboard. Status is already pending_approval from the step saves.

Website backend step numbers (for reference only, do not send current_step from Flutter):
  visual 1 Basic            -> Django step 1
  visual 2 Professional     -> Django step 2
  Lead Preferences modal    -> Django step 6
  visual 3 Product Portfolio-> Django step 4
  visual 4 Additional       -> Django step 5
  Declarations submit       -> Django step 7 (status only)
Flutter ignores those numbers and uses the four PUT endpoints above.

2. LOAD PROFILE — GET /api/v1/agents/profile
================================================================================
Auth: Bearer JWT. Role in the token must be "agent".
Success 200 body shape:

{
  "success": true,
  "agent": { ... },
  "profile": { ... },
  "features_access": { "<feature_slug>": { ... } }
}

agent fields you must bind:
  id, status, badge, fullname, email, mobile,
  experience_range, client_base, user_types,
  activeSubscription.selected_plan,
  insuranceSegments[].segment_type,
  productExpertise[]: { segment_type, product_name, expertise_level, is_custom },
  serviceableCities: ["Ahmedabad", ...],
  familyLicenses[]: { full_name, member_name, relationship, license_number, license_type },
  performanceStats: { claims_processed, claims_settled, claims_amount, success_rate, response_time },
  portfolios[]: { segment_type, primary_companies, secondary_companies },
  careerTimelines[]: { month, year, type, event_text, title },
  achievementPhotos[]: { id, photo_url },
  leadPreferences: {
    leads_new_business, leads_portfolio_analysis, portfolio_charging, portfolio_fee,
    leads_claims_support, claims_charging, claims_fee_amount, claims_percent
  } or null

profile fields you must bind:
  profile_photo_url, display_name, whatsapp, languages, address, date_of_birth,
  pan_number, license_number, license_valid_till, irdai_license_doc,
  arn_number, euin_number, investment_valid_till, amfi_license_doc,
  investment_types: ["SIP/STP/SWP", ...],
  agency_name, office_address,
  service_pincodes[]: { pincode, city_name, selected_areas: [], postal_data: [] },
  has_pos_license, career_highlights, website,
  social_links: { google_business, linkedin_url, instagram_url, facebook_url, youtube_url }

languages is one comma-separated string, lowercase, no spaces: "english,hindi,gujarati"
date fields are "YYYY-MM-DD" or null.
Photo and document URLs may be absolute (Cloudinary) or start with /media/. Prefix the app base URL when the value starts with /.

IMPORTANT: careerTimelines inside this GET often have no id.
For edit and delete, also call GET /api/v1/agents/profile/career-timeline which returns id.

features_access item shape:
{
  "feature_slug": "edit_profile_basic",
  "label": "Edit Profile: Basic Details",
  "is_locked": false,
  "unlocked_by": "plan",
  "unlock_hint": null,
  "upgrade_required": false
}
If is_locked is true, show unlock_hint and do not call the write API.

Feature slugs that gate this screen:
  edit_profile_basic            whole Step A
  edit_profile_professional     whole Step B text save
  edit_profile_certifications   IRDAI and AMFI file upload only
  edit_profile_claim_support    only if you send performanceStats
  lead_preferences              only if you send leadPreferences
  receive_leads                 New Business toggle (plan)
  lead_portfolio_analysis       Portfolio Analysis toggle (plan)
  lead_claims_support           Claims Support toggle (plan)
  edit_profile_portfolio        whole Step C
  manage_portfolio              required when portfolios array is not empty
  edit_profile_companies        required when a portfolio object contains companies
  edit_profile_additional       whole Step D text save
  upload_achievements           achievement photo upload and delete
  edit_profile_social_media     required when website or any social link changed
  edit_profile_professional_bio required when career_highlights text changed
  edit_profile_career_timeline  career timeline create, update, delete

Locked API response is HTTP 403:
{
  "detail": {
    "success": false,
    "error_code": "FEATURE_LOCKED",
    "feature": "edit_profile_basic",
    "message": "Edit Profile: Basic Details is locked on your current plan.",
    "unlock_hint": "Upgrade to Starter or Professional Plan to unlock",
    "upgrade_required": true
  }

Show message + unlock_hint. Do not retry.

3. STEP A — BASIC DETAILS
================================================================================
Field count on screen: 9 inputs + 2 UI-only checkboxes.
JSON fields sent to the API: 8.
Separate upload: 1 file.

SCREEN FIELDS
#  UI label                         JSON path                    Required   Notes
1  Profile photo                    (not in JSON)                no         POST /profile/image, field name "file"
2  Your Full Name                   agent.fullname               YES        letters and spaces only
3  Display Name (Public Profile)    profile.display_name         no
4  Same as full name                UI only                      no         copies fullname into display_name
5  Mobile Number (Calling)          agent.mobile                 YES        digits only
6  WhatsApp Number                  profile.whatsapp             no         digits only
7  Same as mobile number            UI only                      no         copies mobile into whatsapp and locks the box
8  Email ID                         agent.email                  YES        also the login email
9  Languages You Speak              profile.languages            YES        multi-select, stored as one string
10 Residence Address                profile.address              YES        textarea
11 Date of Birth                    profile.date_of_birth        no         date picker, send null if empty

Language options (store the value, show the label):
  english, hindi, gujarati, marathi, tamil, telugu, kannada, bengali, punjabi
Join selected values with a comma and no spaces: "hindi,gujarati"
At least one language is required.

CLIENT VALIDATION (match the website, then the API)
  fullname
    - required, trim
    - allow only A-Z, a-z, and spaces
    - website max length 70; server max 255. Use 70 in the UI.
    - error: "Full Name is required"
  display_name
    - optional
    - letters and spaces only
    - website max length 35; server max 255. Use 35 in the UI.
  mobile
    - required
    - digits only, exactly 10 digits in the UI
    - server accepts 10 to 15 digits
    - error: "Mobile Number is required"
  whatsapp
    - optional
    - if filled: digits only, 10 digits in the UI
    - server: if filled, 10 to 20 digits, else "Enter a valid WhatsApp number."
  email
    - required
    - valid email
    - server also rejects a duplicate (another agent already has it)
  languages
    - required, at least one
    - error: "At least one language is required"
    - server max 255 characters on the joined string
  address
    - required, trim
    - server max 255
    - error: "Residence Address is required"
    - placeholder: "Society/Building Name, Area, City, Pincode"
  date_of_birth
    - optional
    - send "YYYY-MM-DD" or null
    - do not send ""

API
PUT /api/v1/agents/profile/basic
Feature lock checked first: edit_profile_basic
Does not touch professional, portfolio, additional, photo, licenses, cities, or leads.

Request:
{
  "agent": {
    "fullname": "Ashish Prajapati",
    "email": "ashish@example.com",
    "mobile": "9876543210"
  },
  "profile": {
    "display_name": "Ashish",
    "whatsapp": "9876543210",
    "languages": "hindi,gujarati",
    "address": "12 Shanti Society, Navrangpura, Ahmedabad, 380009",
    "date_of_birth": "1990-05-21"
  }
}

Server checks (in order):
  1. fullname non-empty after trim -> 422 "Full name is required."
  2. email non-empty -> 422 "Email is required."
  3. mobile non-empty -> 422 "Mobile number is required."
  4. languages non-empty -> 422 "Languages are required."
  5. address non-empty -> 422 "Residence address is required."
  6. email unique among other agents -> 409 "The email has already been taken."
  7. feature edit_profile_basic unlocked -> else 403 FEATURE_LOCKED
  8. writes agents.fullname, agents.email, agents.mobile
  9. if email changed, also updates the login user row so the agent can still sign in
  10. writes profile display_name, whatsapp, languages, address, date_of_birth
  11. sets status pending_approval (unless suspended / blacklisted / rejected)
  12. returns the full GET profile body (AgentProfileResponse)

Pydantic will 422 before the service if fullname, email, mobile, languages, or address keys are missing.
Empty string "" passes Pydantic and fails the service checks above.

PHOTO API (call when the user picks a photo, not inside the basic JSON)
POST /api/v1/agents/profile/image
multipart field name: file
Allowed by API: .jpg .jpeg .png .webp
MIME: image/jpeg, image/jpg, image/png, image/pjpeg, image/webp
Max size: 20 MB
Magic bytes must be real JPEG, PNG, or WEBP. GIF is rejected.
Server re-encodes the image.
Response: { "success": true, "profile_photo_url": "<url>" }
Also sets status pending_approval.
Website UI copy says 5 MB. Follow the API limit of 20 MB, and prefer telling the user "JPG, PNG, or WEBP".

PAN note:
  The website requires PAN and checks format ^[A-Z]{5}[0-9]{4}[A-Z]$ (example ABCDE1234F).
  The mobile professional API does not re-check PAN format. Still enforce the website rule in Flutter so bad PANs are not saved.
  Uppercase, strip non-alphanumeric, max 10.

IRDAI license number:
  The agent cannot type this on the website. Admin sets it after PAN verification.
  Show it read-only. If empty, placeholder "Will be Updated by Admin".
  ALWAYS send the existing license_number back. An empty string overwrites and clears it.

CLIENT VALIDATION
  pan
    - required
    - uppercase, exactly [A-Z]{5}[0-9]{4}[A-Z]
    - error: "PAN Number is required for IRDAI verification"
    - format error: "Please enter a valid PAN Number format (e.g., ABCDE1234F)"
  license_valid_till, investment_valid_till
    - optional dates YYYY-MM-DD or null
  arn_number, euin_number, agency_name, office_address
    - optional
    - agency_name and office_address max 255 if you mirror the website
  service pincode
    - required
    - exactly 6 digits
    - first digit 1-9 (website regex ^[1-9][0-9]{5}$)
    - no duplicate pincodes
    - after 6 valid digits, call the pincode API
  selected areas
    - required, at least one area per pincode
    - server error: "Please select at least one area for pincode {pincode}."
    - server error if none: "At least one service pincode is required."
    - server error if duplicate: "Duplicate pincode detected: {pincode}"
  serviceable cities
    - required, at least one name
    - user may search the list or add a new city name
  experience_range
    - required in the app
    - digits only, 0 to 60, max 2 digits
    - store as a string, e.g. "15" (the column is text, not an int)
    - error: "Years of Experience is required"
  client_base
    - required in the app
    - digits only, min 0, max 5 digits
    - store as a string, e.g. "500"
    - error: "Client Base is required"
  has_pos_license
    - boolean. Yes = true, No = false. Default false.
    - if the user never touches it, still send false. Do not omit it in a way that flips a saved true to false by accident: bind the radio from the GET value.
  family row (only saved when name is non-empty)
    - full_name: text, "Name as per license"
    - relationship: one of father, mother, spouse, son, daughter, brother, sister, other
    - license_number: PAN or IRDAI license text, optional
    - sending [] deletes every family license. Send the full current list.
  claims (only include performanceStats if edit_profile_claim_support is unlocked)
    - claims_processed: integer >= 0
    - claims_settled: integer >= 0
    - claims_settled must be <= claims_processed
      error: "Settled claims cannot exceed processed claims"
    - if settled > 0 and processed is 0:
      error: "Processed claims are required if claims were settled"
    - claims_amount: digits only, max 10 digits, >= 0
    - success_rate is read-only: round((settled / processed) * 100, 2) when processed > 0, else 0
    - response_time is not on the website form. If you send performanceStats, pass the existing response_time from GET, or "2". The server stores the first integer it finds in that value. Default 2.
    - if the claims block is locked, OMIT performanceStats (null). Sending it returns 403 and the whole step fails.

PROFESSIONAL SAVE
PUT /api/v1/agents/profile/professional
Locks:
  always: edit_profile_professional
  if performanceStats is not null: edit_profile_claim_support
  if leadPreferences is not null: lead_preferences

This call REPLACES:
  all service pincodes
  all serviceable cities
  all family licenses
And OVERWRITES scalar professional fields, including license_number.
It does not touch basic info, photo, segments, portfolios, bio, or social links.
License document files are not part of this JSON.

{

    "experience_range": "15",

      "claims_settled": 145,
      "claims_amount": 2500000,
      "success_rate": 0,
      "response_time": "2"
    },
    "leadPreferences": null
  },
  "profile": {
    "pan_number": "ABCDE1234F",
    "license_number": "IRDAI-EXISTING-OR-EMPTY-IF-NEVER-SET",
    "license_valid_till": "2027-03-31",
    "arn_number": "ARN-123456",
    "euin_number": "E123456",
    "investment_valid_till": "2027-03-31",

If claims are locked, set performanceStats to null.
If leads are locked, set leadPreferences to null.
success_rate in the request is ignored. Server recomputes it.
Family name mapping: server uses full_name, else member_name.
Family license mapping: server uses license_number, else license_type.
Send both pairs with the same value so older readers stay in sync.

Server writes strings for claims_processed, claims_settled, claims_amount, success_rate.
response_time is stored as an integer (default 2).

Returns the full profile.

LEAD PREFERENCES (same professional PUT, sheet on Step B)
Include this object only when lead_preferences is unlocked.
Website requires at least one enabled lead type to be checked.
If every toggle is disabled by the plan, skip validation and omit the object.

{
  "leads_new_business": true,
  "leads_portfolio_analysis": false,
  "portfolio_charging": "free",
  "portfolio_fee": 0,
  "leads_claims_support": false,
  "claims_charging": "free",
  "claims_fee_amount": 0,
  "claims_percent": 0
}

Toggles:
  1. New Business
     JSON: leads_new_business
     Plan feature: receive_leads
     Experience: all agents
     No fee fields
  2. Portfolio Analysis
     JSON: leads_portfolio_analysis
     Plan feature: lead_portfolio_analysis
     Experience gate: agent.experience_range must parse to >= 5 years
     If under 5 years, show locked: "Requires N more year(s) of experience"
     Charging (only when the toggle is on):
       portfolio_charging = "free" | "conditional" | "paid"
       free: portfolio_fee = 0, hide amount
       conditional: show "Consultation Fee" and send that number as portfolio_fee (>= 0)
       paid: show "Consultation Fee" and send that number as portfolio_fee (>= 0)
  3. Claims Support
     JSON: leads_claims_support
     Plan feature: lead_claims_support
     Experience gate: >= 10 years
     Charging:
       claims_charging = "free" | "fee" | "percentage"
       free: claims_fee_amount = 0, claims_percent = 0
       fee: send claims_fee_amount >= 0, claims_percent = 0
       percentage: send claims_percent from 0 to 10, claims_fee_amount = 0
       UI: if percent < 0 clamp to 0; if percent > 10 clamp to 10

SERVER EXPERIENCE GATE (applied even if the app sends true):
  Parse the first integer in experience_range.
  If years < 5:
    force leads_portfolio_analysis = false
    force portfolio_charging = "free", portfolio_fee = 0
    force leads_claims_support = false
    force claims_charging = "free", claims_fee_amount = 0, claims_percent = 0
  If years >= 5 and years < 10:
    force leads_claims_support = false and zero the claims fee fields
  New business is not experience-gated.

Also hide a card when its plan feature is locked (data-plan-locked on the website).
Do not send a lead type the plan has locked as true.

COMPANY DROPDOWN
GET /api/v1/agents/profile/companies
Auth required.
Response is an object, not a list:
{
  "health": ["Acko General Insurance Limited", "..."],
  "life": ["Life Insurance Corporation of India", "..."],
  "motor": ["..."],
  "sme": ["..."]
}
Use the array for that segment. If a saved company is missing from the list, still show it as a selected option.

CLIENT VALIDATION
  For every checked segment, primary company is required.
  Error banner: "Please select a primary company for each segment"
  Percents: number, min 0, max 100. Optional.
  Investment types: optional.
  Unchecking every segment is allowed. Send insuranceSegments: [] and portfolios: [].
  That deletes old segment rows and old portfolio rows. That is intended.

REPLACE WARNING
PUT /profile/portfolio deletes then reinserts:
  insurance segments
  product expertise
  portfolios
If the app does not edit product expertise (the current website does not show an expertise-rating form), you MUST echo agent.productExpertise from GET or the save wipes it.

Expertise item:
{
  "segment_type": "health",
  "product_name": "Family Floater",
  "expertise_level": 3,
  "is_custom": false
}
expertise_level is an int, default 1. Only levels > 0 are stored on the website. Send the GET list back unchanged.
If segment_type is blank, the server guesses: term/life -> life, health/medical -> health, car/motor/bike -> motor, sme/commercial/business -> sme, else life.

PORTFOLIO JSON (this is the shape stored in the database)
Build one object per segment that has a primary company:

{
  "segment_type": "health",
  "primary_companies": {
    "name": "Star Health & Allied Insurance Co. Ltd.",
    "percentage": "60"
  },
  "secondary_companies": {
    "name": "Niva Bupa Health Insurance Company Limited",
    "percentage": "25",
    "others": "",
    "companies": [
      { "name": "Star Health & Allied Insurance Co. Ltd.", "percent": "60" },
      { "name": "Niva Bupa Health Insurance Company Limited", "percent": "25" },
      { "name": "Care Health Insurance Ltd.", "percent": "15" }
    ]
  }
}

primary_companies = the primary name + percentage.
secondary_companies.name / percentage = the secondary company (empty string if none).
secondary_companies.companies = primary, then secondary if present, then each extra row that has a name.
Store percents as strings to match the website.
When you read GET portfolios, primary_companies and secondary_companies are already objects (sometimes they were stored as JSON strings; the API parses them).

API
PUT /api/v1/agents/profile/portfolio
Locks:
  always: edit_profile_portfolio
  if portfolios is not empty: manage_portfolio
  if any portfolio has a non-empty primary_companies or secondary_companies object: edit_profile_companies

Request:
{
  "agent": {
    "insuranceSegments": [
      { "segment_type": "health" },
      { "segment_type": "life" }
    ],
    "productExpertise": [],
    "portfolios": [ { "...as above..." } ]
  },
  "profile": {
    "investment_types": ["SIP/STP/SWP", "Lumpsum"]
  }
}

profile may be omitted. If you omit it, investment types are left unchanged.
If you send profile.investment_types, that list replaces the saved list.
Empty portfolios deletes all company tie-ups.
Returns the full profile.
Sets status pending_approval.

Lock: upload_achievements

Empty: 400 "No files uploaded."

8. ERRORS THE APP MUST HANDLE
================================================================================
401  Token missing, expired, revoked, or role is not agent.
       Body detail: "Could not validate credentials" or "Token is invalid or has been revoked"
       Action: send the user to login.
403  FEATURE_LOCKED object (see section 2). Show the lock message. Do not wipe the form.
404  Agent, photo, or timeline row not found.
409  "The email has already been taken." Highlight the email field.
422  Either a string detail ("Full name is required.", "At least one service pincode is required.", "Please select at least one area for pincode 380001.", "Duplicate pincode detected: 380001.", "Pincode must be exactly 6 digits.", "Achievement photo limit exceeded...")
       or a Pydantic list:
       { "detail": [ { "loc": ["body","profile","languages"], "msg": "Field required", "type": "missing" } ] }
       Map loc to the field and show msg.
500  "An error occurred while updating the profile." or upload storage failure. Ask the user to retry.
503  Pincode lookup upstream down.

Website validation error shape (Django only, not used by Flutter):
{ "status": "error", "message": "Validation failed", "errors": { "full_name": ["The full name field is required."] } }

9. REPLACE-LIST SAFETY CHECKLIST
================================================================================
Do this or the APK will delete data the user already saved.

basic PUT
  Safe. Only the 6 profile/agent scalars. Photo stays on the image API.

professional PUT
  Sends the FULL familyLicenses array or you delete family members.
  Sends the FULL service_pincodes array or you delete pincodes.
  Sends the FULL serviceableCities array or you delete cities.
  Echo license_number.
  performanceStats null means "do not touch claims". An object overwrites all claim numbers.
  leadPreferences null means "do not touch leads". An object overwrites all lead flags, then the server may force some off because of experience.

portfolio PUT
  Sends the FULL insuranceSegments array.
  Sends the FULL portfolios array.
  Echo productExpertise from GET if the screen does not edit expertise.
  investment_types inside profile replaces the list. Omit profile to leave investment types as they are.

additional PUT
  Overwrites website, all 5 social keys, and career_highlights.
  Send the full social_links object every time. A missing key becomes empty and can trip the social lock or clear a link.
  Does not touch achievement photos or timeline rows. Those are the other APIs.

image / achievement / license / timeline
  Each is its own call. Do not also stuff those files into the JSON puts.
